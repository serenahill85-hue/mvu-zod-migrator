# 续章 · MVU Zod 存档迁移助手 v0.5.1

读取角色卡的 MVU Zod 结构脚本、所选新版世界书规则和旧存档，通过 AI 提出迁移方案；核对差异后，备份并写入目标聊天。支持聊天 JSONL 提取、手动编辑变量、多轮反馈，以及直接导入新版变量文件。

## 通过 GitHub 链接安装

前置：安装并启用[酒馆助手](https://github.com/N0VI028/JS-Slash-Runner)。扩展入口要求 SillyTavern 1.19.0 或以上，接口依据酒馆助手 4.11.3 核对，启动时检查必需能力。

1. 打开 SillyTavern 顶部「扩展」→「安装扩展」。
2. 粘贴下面的仓库地址，完成安装后刷新酒馆。
3. 点击页面右上侧「存档迁移」。如果提示缺少酒馆助手，先启用助手再刷新。

```text
https://github.com/serenahill85-hue/mvu-zod-migrator
```

扩展与 JSON 脚本使用同一份功能源码。选择一种安装方式即可；如果以前导入过 JSON 脚本，改用扩展时请停用旧脚本。扩展不会偷偷向全局脚本库添加副本，也不会在安装时读取聊天或调用模型。

更新时在酒馆扩展管理中检查更新并刷新。停用或卸载扩展后刷新即可移除入口；浏览器中的迁移备份保留。

## 下载 JSON 脚本

[下载 v0.5.1 脚本 JSON](https://github.com/serenahill85-hue/mvu-zod-migrator/releases/download/v0.5.1/mvu-zod-migrator.json) · [版本说明](https://github.com/serenahill85-hue/mvu-zod-migrator/releases/tag/v0.5.1)

下载后，在酒馆助手「脚本」→「导入」中选择 JSON，放入全局脚本区并手动启用。酒馆助手 4.11.3 的此入口使用文件选择器，不支持直接粘贴仓库 URL。导入文件默认停用，并分配新的运行 ID，因此更新时应停用或删除旧条目，避免重复运行。

可通过「打开迁移助手」脚本按钮或页面右上侧「存档迁移」打开。仓库地址用于「安装扩展」，JSON 文件用于酒馆助手「导入」。

已去掉脚本自设的 120 秒模型回复超时。请求会一直等待至返回、接口报错或主动取消；手动取消、切换聊天后的迟到结果隔离继续生效。酒馆、代理或 API 服务自身的超时不由本脚本控制。源码依赖下载的 8 秒保护属于读取文件，未改动。

当前为公开试用版。离线和模拟宿主检查已完成；实际模型、真实酒馆安装与重载持久化尚待验证，详见 [验证状态与边界](STATUS.md)。请先在聊天副本试用。

## 给玩家的文件

- `dist/mvu-zod-migrator.json`：导入酒馆助手的脚本文件。
- `dist/mvu-zod-migrator.js`：同一脚本的可查看源码包，无需另行导入。
- `dist/SHA256SUMS.txt`：下载文件的 SHA-256 校验值。
- `manifest.json`、`extension.js`：通过仓库地址安装的扩展入口。
- `STATUS.md`：验证结果与已知边界。

使用扩展安装时，酒馆会从仓库加载对应文件，无需额外导入 JSON。

## 使用顺序

1. 在“提取旧聊天 / 存档变量”选择变量 JSON、工具存档或酒馆聊天 JSONL；也可在旧聊天中点击“提取当前聊天”。“读取指定旧楼层 / 导出结构”可更改旧楼层编号，旧来源与新版目标的楼层设置相互独立。
2. 导入聊天后核对楼层和分支。“查看 / 编辑旧变量”可修改提取出的 JSON，点击“应用旧变量编辑”后生效。“下载提取的变量”只导出 `{"stat_data": ...}`，无需读取新版目标或调用 AI；原聊天文件不变。需要一起保留旧结构时使用折叠区中的“导出旧存档与结构”。不提取旧版世界书规则、不发送聊天正文或重放更新指令。
3. 打开新版卡的目标聊天，点击“读取新版目标”。目标楼层需要已有 MVU 状态；工具不初始化角色卡。可展开“指定读取楼层”，`-1` 自动寻找最近一个有对象形式 `stat_data` 的楼层，编号从 0 开始。初次试用请选择聊天副本。
4. 核对新版结构脚本。旧版结构源码仍可选填；旧存档即使附带旧版更新规则，也会丢弃这部分规则。
5. 展开“查看与选择世界书条目”，搜索书名、选择世界书，再搜索条目名称或正文并勾选。可选未绑定到当前角色的书，支持跨书选择、只看已选、清空选择和查看原文。当前关联书仍提供初筛建议，需要自行核对版本与用途。选择不会改变原世界书内容或开关。
6. 进入“AI 分析”，选择酒馆当前连接，或填写独立 API 地址、模型与密钥。可在“迁移要求（可选）”中说明需要保留或调整的内容。密钥只用于当前面板会话，关闭面板会清空，不进入导出文件。
7. 点击“分析并生成迁移预览”。发送旧变量、所选新版结构与规则、可选旧结构、静态检查结果及玩家要求。未选条目、旧版更新规则和聊天正文不参与分析。格式或已知结构不合格时最多自动修正一次；每次分析、反馈重算和自动修正都可能产生模型调用。可随时取消，不设固定回复等待时限。
8. 核对差异和待选择问题。可在“编辑迁移结果”中修改 JSON，点击“检查并更新结果”，重新检查结构、差异和确认。也可填写“补充修改意见”让 AI 调整；它会收到上一方案、已选答案、手动修改的结果及历次反馈，并始终从旧来源生成完整方案，避免重复换算。AI 失败或取消后可查看旧预览并重试，不能直接应用失败前的预览。
9. 确认最终结果后勾选确认，点击“备份并应用到目标聊天”。只替换该楼层当前分支的 `stat_data`，先备份，再写入、保存和读回。已知结构错误阻止写入；部分检查需要额外确认。反馈后需重新确认。
10. 从“备份与恢复”下载或恢复备份。恢复会再次检查聊天、楼层、分支、消息和变量，避免覆盖后来游玩的进度。

已有新版变量文件时：先“读取新版目标”，在“导入新版变量存档”选择文件，即可预览替换差异，再确认备份与写入。支持纯变量对象、`stat_data` 包装和本工具导出的新版变量存档；不调用 AI，不自动执行原脚本或导入文件中的规则。仍按当前选定的新版结构检查，已知错误阻止写入，缺少结构时须确认检查范围。

底部“清空内容”清掉本次来源、目标、规则选择、源码、连接输入、密钥、反馈和结果，回到准备页。分析中点击会取消并拒收迟到回复；实际读取或保存中按钮暂不可用。聊天数据、已下载文件和本地备份保留。

桌面通过顶栏空白拖动面板；聚焦顶栏后可用方向键移动，Shift 加速。桌面位置保存在本机浏览器，窗口变小时自动限制在可见范围。手机窄屏（640px 及以下）和触摸主指针设备关闭拖动，不套用桌面位置。页面只保留右上角一个关闭键，无移动按钮、居中按钮或底部收起按钮；常驻“存档迁移”入口固定在页面右上侧。

生成中写入仍会停止；结束后可以重试同一预览，无需重复调用 AI。若聊天、楼层、分支或变量已经改变，则必须重新读取。原来把提示词试运行也记为忙碌的问题已修正，优先读取当前酒馆的生成状态；实际酒馆版本与事件时序仍需试用确认。

## 迁移结果与文件格式

结果页展示：迁移概况、字段新增/改动/删除、待处理问题、前后值、原因和源码检查边界。模型输出是受限的 JSON 动作；不会执行 AI 生成的 JS/SQL。合法的 0、false、空字符串、null 与未涉及的旧字段不会因简单合并被清空。

“下载新版变量存档”导出 `format: mvu-zod-migration, kind: result`；可用这个工具重新导入。它不是酒馆原生聊天 JSONL 文件。“下载迁移报告”用于检查，不能当作变量导入。备份使用独立格式并保存迁移前后完整消息变量，不能混入普通旧变量入口。

迁移预览生成不代表写入成功。只有保存及读回核验完成才显示完成状态。工具不迁移全部历史楼层、历史分支、聊天正文、世界书记忆、数据库插件、群聊或其他脚本各自管理的状态；回退旧楼层并不保证兼容新版。

## 源码检查的实际能力

只使用新版世界书规则。条目启用不等于本轮聊天实际激活；宏、EJS 和条件模板只读取原文，不自动展开跨条目引用。全部世界书只先读取名称，未绑定书的正文在玩家打开时读取；未选条目不发送。规则缺失、未启用、手动提供或含动态模板时保留提示。分析前、回复后和写入前复核所选条目的正文、启用及触发配置，包括玩家手动选中的未绑定书。

聊天导入支持原生 JSONL、原生消息数组、含 `chat` 数组的 JSON 和单条原生消息，只提取 `variables[分支编号].stat_data`（包括数字键对象形式的分支表）。不扫描正文猜测变量，不合并不同楼层或分支。文件上限 64 MiB；每份提取变量仍遵守 8 MiB、10 万节点和 64 层限制。没有保存 MVU 的纯文本聊天无法还原，工具会明确报错。原始聊天文件保持不变。

AI 不应把“每轮增加”“每日重置”等游玩规则当成迁移时应执行的操作。规则与 Zod 矛盾、版本对应不明或需要解释的换算，仍需核对模型的警告、理由和问题选择；本地结构检查不能证明自然语言规则已全部满足。

第一版使用 Acorn 解析源码，只解释受支持的 **Zod 4 静态子集**：常量、对象、数组、动态字典、枚举、字面量、默认值、可选与可空字段、部分类型转换和常用范围约束。不直接执行整段角色卡脚本，也不把任意代码交给浏览器求值。

自定义 preprocess/transform/refine、闭包、动态默认值、运行时修改或无法解析的模块引用会标为部分检查；不能声称运行了原始 Zod。`catch` 不会静默把非法旧值换成默认值，`pipe` 只检查可确认的输入侧。静态检查无法完整证明旧字段与新字段的含义一致，这部分由 AI 提出建议并呈现给玩家确认。

外部依赖只进行有数量、长度和超时限制的文本读取，允许常见源码 CDN 与 GitHub 原始文件域名，不执行下载内容。动态地址、浏览器跨域限制、依赖未取到或引用未解析会保留缺口；不会虚构完整结构。模型提示中保留原始源码供分析。

当前依据酒馆助手 4.11.3 和 SillyTavern 1.19.0 的固定源码快照实施，并在运行时检测所需能力。“最新版”会继续变化；缺少所需接口时工具会报出缺项。所有写入保护仍不能替代实际环境验证，尤其是多个浏览器标签页同时操作、其他扩展对生成请求的改写及角色卡的特殊生命周期。

## 开发与复核

Node.js 20 或以上。不需要 npm install；Acorn 已固定版本并随包提供，许可证见 THIRD_PARTY.md。

```text
node --test tests/*.test.mjs
node tools/build.mjs
node tools/build.mjs --check
```

可选设置环境变量 `MIGRATOR_ZOD_ORACLE` 指向本机现有 Zod 4 模块，运行静态子集对照；没有该模块时仅跳过此附加对照，不影响脚本运行。

`preview/` 使用维护源构建包、模拟酒馆和模拟模型，不连接真实 API。通过本地 HTTP 服务打开 `preview/index.html`；`preview/responsive.html` 用实际 320/390 CSS px 容器检查布局。不要把模拟成功当成真实酒馆验收。
